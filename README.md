## 🎯 ที่มาและวัตถุประสงค์

กาญจนบุรีมีสองด้านซ้อนกันอยู่ในพื้นที่เดียว ด้านหนึ่งคือป่าอนุรักษ์ผืนใหญ่ (อุทยานแห่งชาติและเขตรักษาพันธุ์สัตว์ป่า) ที่เกิดไฟป่าทุกปีในช่วงฤดูแล้ง อีกด้านคือการปลูกทุเรียนที่ขยายตัวเร็วมาก จากข้อมูลที่ใช้ พื้นที่ปลูกทุเรียนรวมเพิ่มจาก **2,354 ไร่ (พ.ศ. 2561)** เป็น **13,732 ไร่ (พ.ศ. 2568)** หรือประมาณ **5.8 เท่า**

คำถามของโครงการคือ **ไฟป่าเกิดเมื่อไหร่ เกิดที่ไหน และเมื่อเทียบกับพื้นที่ปลูกทุเรียนแล้วเห็นอะไรบ้าง** โดยมีเป้าหมายเพื่อสร้างเครื่องมือที่ช่วยให้เห็นภาพรวมและรูปแบบของไฟป่า

| # | คำถามที่แดชบอร์ดตอบ | ส่วนในแดชบอร์ด |
|---|---|---|
| 1 | จุดความร้อนเกิดเมื่อไหร่ | ส่วนที่ 1: รายเดือนแยกปี, ฤดูกาล, Heatmap เดือน × ปี, ช่วงเวลาที่ดาวเทียมตรวจพบ |
| 2 | เกิดที่ไหน และในป่าประเภทไหน | ส่วนที่ 2: แผนที่ (จุดพิกัด / ความหนาแน่น), ระดับความเชื่อมั่น |
| 3 | ภาพรวมเพิ่มเติมและความเชื่อมโยงกับพื้นที่ปลูกทุเรียน | ส่วนที่ 3: ประเภทป่า, จำนวนวันที่พบไฟรายตำบล, อำเภอ × ประเภทป่า, แนวโน้มทุเรียน, Scatter |

ข้อกำหนดด้านการสื่อสารที่กำหนดไว้ตั้งแต่เอกสาร BRD คือ **ต้องมีข้อความเตือนการตีความ** ในหลายจุด เพื่อไม่ให้ผู้ใช้สรุปเกินกว่าที่ข้อมูลบอกได้

## 🧹 การเตรียมข้อมูล (Data Preparation)

แบ่งเป็นสองชั้น: **(1) เตรียมข้อมูลดิบให้เป็นตารางที่พร้อมใช้** (`data_prep.py`) และ **(2) แดชบอร์ดที่อ่านตารางเหล่านั้น** (`app.py`) ทำให้ทุกกราฟใช้ตัวเลขชุดเดียวกัน ไฟล์ดิบในโฟลเดอร์ `data/` เก็บไว้ครบ ไม่มีการแก้ไขหรือลบ

แดชบอร์ดอ่านตารางที่เตรียมไว้ 3 ตาราง:

| ตาราง | เนื้อหา |
|---|---|
| `hotspot_events.parquet` | เหตุการณ์จุดความร้อนรายจุด (หลังกรอง) |
| `hotspot_agg.parquet` | จำนวนจุดความร้อนสรุปรายอำเภอ/ตำบล/ปี |
| `joined_table.parquet` | ตารางรวมจุดความร้อน + พื้นที่ทุเรียน (1 แถว = 1 ตำบลใน 1 ปี) |

### ขั้นตอนที่ 1: จัดรูปแบบวันที่ เวลา และชื่อพื้นที่

- วันที่ดิบอยู่ในรูป `19-พ.ย.-23` (เดือนอักษรย่อไทย, ปีสองหลักแบบ ค.ศ.) → แปลงเป็นวันที่จริงในคอลัมน์ `date_parsed` เพื่อแยกเดือนและปี
- ปีที่ใช้เชื่อมกับข้อมูลทุเรียนต้องเป็น **พ.ศ.** (ค.ศ. + 543)
- เวลาที่ดาวเทียมตรวจพบ → แยกเป็น `time_hhmm` (HH:MM) และ `hour_of_day` เพื่อทำกราฟช่วงเวลาที่ดาวเทียมผ่าน
- `อำเภอ_norm`, `ตำบล_norm` → ลบช่องว่างทั้งหมดเพื่อให้ชื่อจากสองไฟล์เทียบกันตรงกัน และใช้เป็นคีย์เชื่อมข้อมูล

### ขั้นตอนที่ 2: คัดแถวที่ไม่ใช่ไฟป่าจริงออก

ข้อมูลดิบ 8,606 จุด แต่ไม่ใช่ทุกจุดที่เป็นไฟป่าจริง คัดออกโดยดูจากคอลัมน์หมายเหตุ:

| กลุ่มที่ตัดออก | จำนวน | เหตุผล |
|---|---|---|
| การจัดการเชื้อเพลิง | 732 | งานจัดการเชื้อไฟในป่า ไม่ใช่ไฟป่าที่เกิดขึ้นเอง |
| เจ้าหน้าที่เข้าตรวจสอบแล้วไม่พบไฟ | 6 | ไม่มีไฟจริง |
| พิกัดที่อยู่ระหว่างดำเนินคดี | 3 | ไม่ใช่ไฟป่าตามธรรมชาติ |
| **รวมตัดออก** | **741** | |

**8,606 − 741 = 7,865 จุด** คือตัวเลขที่ใช้ทั้งแดชบอร์ด (ถ้านับรวมจุดเหล่านี้จะทำให้เข้าใจผิดว่ามีไฟป่า) ข้อมูลดิบยังเก็บไว้ครบ และโค้ดอ่านคอลัมน์หมายเหตุซ้ำเพื่อนับแถวที่คัดออกและแสดงให้ผู้ใช้เห็นอย่างโปร่งใส

### ขั้นตอนที่ 3: ย่อและรวมสองชุดข้อมูล (ขั้นตอนที่ต้องระวังที่สุด)

ข้อมูลไฟเป็นรายจุด แต่ทุเรียนเป็นรายตำบลต่อปี ถ้านำจุดไฟรายจุดไป JOIN กับตารางทุเรียนตรงๆ พื้นที่ทุเรียนของตำบลหนึ่งจะ **ถูกคัดลอกซ้ำตามจำนวนจุดไฟ** ทำให้ยอดพื้นที่รวมบวมเกินจริง จึงทำดังนี้:

1. **Aggregate** จุดไฟเป็นจำนวนจุดต่อตำบลต่อปี
   `Group by [จังหวัด, อำเภอ_norm, ตำบล_norm, พ.ศ.] → hotspot_count = count(LAT)`
2. **OUTER JOIN** กับพื้นที่ทุเรียนด้วยคีย์ `[อำเภอ_norm, ตำบล_norm, พ.ศ.]`
   (ต้องใช้คู่ อำเภอ + ตำบลเสมอ เพราะชื่อตำบลซ้ำกันข้ามอำเภอได้)

ผลลัพธ์คือตารางรวมที่ **1 แถว = 1 ตำบลใน 1 ปี** มี 2 ค่า คือ `hotspot_count` และ `durian_area_rai`

### กฎการจัดการค่าว่างหลัง JOIN

| กรณี | การจัดการ | ความหมาย |
|---|---|---|
| `hotspot_count` เป็น NaN | แทนด้วย **0** | ตำบลมีทุเรียนแต่ไม่พบจุดความร้อนในปีนั้น |
| `durian_area_rai` เป็น NaN | **คงไว้เป็น NaN (Missing)** ห้ามแทนด้วย 0 | ไม่มีข้อมูลสำรวจ |
| `durian_area_rai` = 0 | แสดงเป็น **🟡 0.0 ไร่** | ค่า 0 จริงที่บันทึกไว้ |

ตารางและกราฟแสดง 🟡 **0.0 ไร่** กับ ⬜ **Missing** เป็นสถานะที่ต่างกันอย่างชัดเจน

**ชั้นที่ 2: ตรวจพิกัดซ้ำซ้อนและแสดงผลบนหน้าจอ** (ท้ายหน้าแดชบอร์ด)

**ชั้นที่ 3: อธิบายส่วนต่างของตัวเลขบนหน้าจอ**
หมายเหตุท้ายหน้าอธิบายว่า ข้อมูลดิบ 8,606 จุด เหลือ 7,865 จุด และช่วงเริ่มต้นของแดชบอร์ด (ค.ศ. 2024–2025) แสดง **7,857 จุด** เพราะไม่รวมอีก 8 จุดของปี ค.ศ. 2023

> หลักการ: ทุก KPI คำนวณจากฟังก์ชันกลางฟังก์ชันเดียว ไม่มีการเขียนตัวเลขตายตัว (hard-code) ในโค้ดแสดงผล และมีคำเตือนบนหน้าจอเมื่อยอดรวมของตารางต่างๆ ไม่ตรงกัน

### ปัญหาที่พบและการตัดสินใจ

1. **จำนวนตำบลของข้อมูลทุเรียนไม่เท่ากันทุกปี** (50 / 64 / 63) → ไม่เติมค่าให้ตำบลที่หายไป และใส่ข้อความเตือนใต้กราฟว่ายอดรวมระหว่างปีไม่ควรเทียบกันตรงๆ
2. **พื้นที่ทุเรียน = 0 ไร่** ในตารางรวมปี 2566–2568 มี 8 ตำบล-ปี → ตรวจแล้วเป็นค่า 0 จริงที่บันทึกไว้ ไม่ใช่ค่าที่หายไป (จำนวนค่า Missing = 0)
3. **คอลัมน์ "ประเภท Hotspot" ผิดคอลัมน์** 1,619 แถวถูกกรอกค่าระดับความเชื่อมั่นผิดช่อง ทำให้ประเภทพื้นที่ที่แท้จริงขาดหาย → **แดชบอร์ดไม่ใช้คอลัมน์นี้** แต่ใช้ "ประเภทป่าอนุรักษ์" ซึ่งครบถ้วน
4. **ข้อมูลไม่เต็มปี** ปี 2566 มีเพียง 2 เดือน ปี 2568 สิ้นสุดเดือนสิงหาคม → แสดงจำนวนเดือนและจำนวนวันที่มีข้อมูลของแต่ละปีไว้ใต้กราฟรายเดือน และแสดงเฉพาะปีที่มีข้อมูลจริง (ไม่พล็อตปีที่ไม่มีข้อมูลเป็น 0)

## 🎨 หลักการออกแบบและฟีเจอร์ของแดชบอร์ด

### หลักการออกแบบ 4 ข้อ

1. **จัดหน้าตามคำถามของผู้ใช้** (เมื่อไหร่ → ที่ไหน → ภาพรวมเพิ่มเติม) ไม่ได้จัดตามชนิดกราฟ
2. **ใช้สีสื่อความหมาย** สีส้ม = ไฟ/จุดความร้อน, สีเขียว = ทุเรียน บนพื้นหลังโทนมืด (Dark Theme) เพื่อให้สีเด่นและอ่านง่าย
3. **แถบเตือนข้อจำกัดอยู่บนสุดของหน้า** และซ้ำใต้กราฟที่เปรียบเทียบไฟกับทุเรียน
4. **ตัวกรองทุกตัวเชื่อมกันทั้งหน้า** เลือกอะไรสักอย่าง ทุกกราฟ แผนที่ และตัวเลขเปลี่ยนตามกัน

### แถบตัวกรองและการ์ดสรุป

**ตัวกรอง 4 ตัว:** อำเภอ · ประเภทป่าอนุรักษ์ · ระดับความเชื่อมั่น · ช่วงปี (ปุ่มเลือกแบบคลิก) — มีป้ายแสดงตัวกรองที่กำลังใช้อยู่ และปุ่ม **ล้างตัวกรอง** เพื่อกลับสู่ภาพรวมทั้งจังหวัด

> **หมายเหตุเรื่อง "เทียบปีก่อนหน้า −76.8%"**: เป็นการเทียบ ค.ศ. 2025 (1,477 จุด) กับ 2024 (6,380 จุด) ในช่วง ม.ค.–พ.ค. ที่ทั้งสองปีมีข้อมูลครบ กุมภาพันธ์ลดจาก 2,156 เหลือ 981, มีนาคมจาก 1,953 เหลือ 232, เมษายนจาก 1,998 เหลือ 14 และเมื่อเทียบเป็นฤดูไฟ พ.ย.–พ.ค. จะได้ 6,378 เทียบ 1,483 จุด (ลดลงราว 76.7%) การลดลงนี้ **เห็นได้ในข้อมูลจริง แต่สาเหตุไม่อยู่ในข้อมูลชุดนี้** และมีเพียงสองฤดู จึงสรุปแนวโน้มระยะยาวไม่ได้ ตัวเลขปี 2566 (2 เดือน) และ 2568 (ถึง ส.ค.) ไม่เต็มปี การเทียบจึงอาจคลาดเคลื่อน

## 🔎 ข้อค้นพบหลัก

1. **ไฟกระจุกในฤดูแล้ง** — 97.3% ของจุดเกิดช่วง พ.ย.–เม.ย. เดือนกุมภาพันธ์สูงสุด 3,137 จุด (39.9%)
2. **ไฟกระจุกเชิงพื้นที่** — ศรีสวัสดิ์และทองผาภูมิรวมกันเกินครึ่งของทั้งหมด ตำบลชะแลสูงสุด 1,087 จุด
3. **ไฟอยู่ในอุทยานแห่งชาติ 62% และเขตรักษาพันธุ์สัตว์ป่า 35.6%** (เกือบ 98% ในสองประเภทแรก)
4. **จุดความร้อนปี ค.ศ. 2025 ลดลงราว 76.8% จากปี 2024** แต่ยังไม่ทราบสาเหตุ
5. **พื้นที่ปลูกทุเรียนเพิ่มต่อเนื่องจาก 2,354 เป็น 13,732 ไร่** แต่ตัวเลขรวมปนผลจากจำนวนตำบลที่มีข้อมูลเพิ่มขึ้น
6. **ไฟกับทุเรียน (ระดับตำบล):** จุดส่วนใหญ่กองอยู่ซ้ายล่าง (ทุเรียนน้อย/ไฟน้อย) ตำบลที่มีไฟมากที่สุดมีทุเรียนไม่มาก ส่วนตำบลที่มีทุเรียนมากกว่าพันไร่ส่วนใหญ่มีไฟไม่สูง และไม่เห็นเส้นแนวโน้มที่ชัดเจน
   - ช่วง พ.ศ. 2566–2568 มี **191 ตำบล-ปี** ในนั้น **183** มีทุเรียน > 0 ไร่ โดย **118 ตำบล-ปี (ราว 64%) ไม่พบจุดความร้อนเลย** (ค่ามัธยฐาน 0 จุด) ส่วนอีก 8 ตำบล-ปีบันทึกทุเรียน 0 ไร่ และไม่พบจุดความร้อน
   - **ค่า 0 จุด ไม่ได้แปลว่าตำบลนั้นปลอดไฟ** เพราะข้อมูลนับเฉพาะป่าอนุรักษ์ ตำบลที่ไม่มีป่าอนุรักษ์จึงไม่มีจุดในข้อมูลโดยธรรมชาติ
   - สรุปได้อย่างปลอดภัยว่า *ในระดับตำบลและด้วยข้อมูลสองฤดูไฟนี้ ยังไม่เห็นรูปแบบความสัมพันธ์ที่ชัดเจน* และข้อมูลนี้บอกไม่ได้ว่าไฟเกิดจากหรือส่งผลต่อสวนทุเรียนหรือไม่

## ⚠️ ข้อจำกัดและการตีความ

1. **เทียบกันที่ระดับตำบล ไม่ใช่ระดับแปลง** — บอกไม่ได้ว่าไฟอยู่ใกล้สวนหรือไม่ (ไม่มี Polygon ของสวนทุเรียน จึงไม่ทำ Distance Analysis)
2. **ข้อมูลไฟครอบคลุมเฉพาะป่าอนุรักษ์** ไม่ใช่ไฟทุกจุดในจังหวัด
3. **ข้อมูลไฟมีเพียงสองฤดู** และปี 2566 มีเพียงสองเดือน จึงสรุปแนวโน้มระยะยาวไม่ได้
4. **จำนวนตำบลของข้อมูลทุเรียนไม่คงที่** ยอดรวมระหว่างปีจึงเทียบกันตรงๆ ไม่ได้
5. **ข้อมูลเป็นการสังเกต ไม่ใช่การทดลอง** จึงสรุปเหตุและผลไม่ได้

**สิ่งที่ตั้งใจไม่ทำ:** ไม่มีสถิติเชิงอนุมาน (เช่น Mann-Whitney U), ไม่มีเส้นแนวโน้ม/Regression บน Scatter, ไม่สร้างอัตราส่วนระหว่างจุดความร้อนกับพื้นที่ทุเรียน และไม่วิเคราะห์ระยะทางเชิงพื้นที่

## 🚀 การติดตั้งและเริ่มใช้งาน

**ความต้องการระบบ:** Python 3 · Windows (PowerShell)

### 1. ติดตั้ง Virtual Environment และ Dependencies
````powershell
# สร้าง venv (หากยังไม่มี)
python -m venv .venv_phase8

# ติดตั้งแพ็กเกจ
.\.venv_phase8\Scripts\pip install -r requirements.txt
````
> ใช้ `.venv_phase8` เท่านั้น เพราะ `.venv` เดิมพังแล้ว (ชี้ไปยัง Python ที่ถูกลบ)

### 2. เตรียมข้อมูล (หากต้องการ Re-generate ไฟล์ Parquet)
````powershell
.\.venv_phase8\Scripts\python data_prep.py
````
ระบบจะรัน Assertion ตรวจสอบจำนวนแถวและผลรวมจุดความร้อนทั้งก่อนและหลัง JOIN

### 3. รันแดชบอร์ด
````powershell
.\.venv_phase8\Scripts\python app.py
````
เปิดเบราว์เซอร์ไปที่ **`http://127.0.0.1:8050/`** (หากพอร์ต 8050 ถูกใช้งานอยู่ ให้ดูพอร์ตที่ระบบแจ้งในหน้าต่างคำสั่ง)

## 🧪 การทดสอบระบบ Cross-Filtering

1. **คลิกจุดบนแผนที่** → ตัวเลข กราฟ และตารางที่เกี่ยวข้องกรองเหลือเฉพาะตำบลนั้น
2. **คลิกช่องใน Heatmap** → ทั้งหน้ากรองตามปีและเดือนที่เลือก
3. **เลือกอำเภอจากตัวกรอง** (เช่น ทองผาภูมิ) → ตัวเลขและกราฟเปลี่ยนตาม
4. **กด "ล้างตัวกรอง"** → กลับสู่ภาพรวมทั้งจังหวัด

สถานะที่ควรทดสอบทุกครั้งหลังแก้โค้ด: ไม่กรอง · เลือก 1 ตำบล · เลือก 1 อำเภอ · ช่วงปีแคบ · ตัวกรองที่ได้ 0 แถว (ต้องแสดงผลได้โดยไม่เกิด Error)
